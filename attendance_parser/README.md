# Attendance Report Converter

כלי Python לעיבוד דוחות נוכחות בפורמט PDF ולהפקת דוחות PDF ו-Excel.

## מה הכלי עושה

- מחלץ טקסט ישירות מקובצי PDF דיגיטליים, ומשתמש ב-OCR של Windows לעמודים סרוקים.
- מזהה דוחות נוכחות מסוג `TYPE_A` ו-`TYPE_B`. דוחות מסוג B ניתנים לזיהוי גם כאשר כותרותיהם נפגעו ב-OCR, לפי מבנה שורות הנוכחות.
- מפענח את הנתונים למודלים המשותפים `AttendanceReport` ו-`AttendanceRow`.
- משנה שעות עבודה בימי עבודה לפי אסטרטגיה המתאימה לסוג הדוח, מחשב מחדש שעות וסיכומים, ומפיק PDF ו-Excel.
- מדווח על קובץ לא מזוהה או על ערך לא תקין במקום להפיק עבורו דוח מטעה; ממשיך לעבד קבצים אחרים בתיקייה.
- משאיר שורות שבת וחג בדוח. שעות הכניסה, היציאה וההפסקה מוצגות כריקות, וסך השעות נשמר.
- מעבד קובץ PDF יחיד או את כל קובצי ה-PDF שבתיקייה, ללא סריקת תיקיות משנה.

## דרישות

- Windows 10 או Windows 11 עבור OCR של Windows.
- Python 3.10 ומעלה.
- חבילת שפה עברית של Windows לזיהוי OCR בעברית. בלעדיה, זיהוי שדות בעברית עלול להיות חלקי.

## התקנה

יש לפתוח PowerShell בתיקיית הפרויקט ולהריץ:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

אם הפעלת סקריפטים חסומה ב-PowerShell, אפשר להפעיל את הסביבה מתוך Command Prompt:

```bat
.venv\Scripts\activate.bat
```

## הפעלה

עיבוד קובצי הדוגמה ושמירת התוצאות בתיקיית ברירת המחדל:

```powershell
python main.py
```

עיבוד תיקייה מסוימת:

```powershell
python main.py "data/sample_reports" --output "data/output_reports"
```

עיבוד קובץ PDF יחיד:

```powershell
python main.py "data/sample_reports/report.pdf" -o "data/output_reports"
```

כדי לעקוף את מטמון הטקסט ולחלץ מחדש, כולל הפעלת OCR לעמודים סרוקים:

```powershell
python main.py "data/sample_reports" --force-ocr
```

הצגת אפשרויות שורת הפקודה:

```powershell
python main.py --help
```

הארגומנט הראשון הוא קובץ PDF או תיקייה. אפשר לציין תיקיית פלט באמצעות `-o` או `--output`. ברירות המחדל הן `data/sample_reports` ו-`data/output_reports`.

## חילוץ טקסט ו-OCR

טקסט שחולץ מכל PDF נשמר ב-`data/text_cache` בקובץ UTF-8 ששמו מבוסס על hash של תוכן ה-PDF והגדרות ה-OCR. עמודים סרוקים מעובדים ברזולוציה של 300 DPI. בהרצה חוזרת, אם הקובץ והגדרות ה-OCR לא השתנו, הטקסט נקרא מהמטמון במקום להריץ חילוץ מחדש. טקסט ריק אינו נשמר במטמון.

האפשרות `--force-ocr` עוקפת את המטמון ומחלצת את הטקסט מחדש. לאחר חילוץ מוצלח, המטמון מתעדכן. ללא האפשרות, התנהגות המטמון הרגילה נשארת ללא שינוי.

ניקוי OCR מתקן שיבושים שנצפו בקובצי הדוגמה, ובהם תאריכים כגון `01102/2023`, `20/1123`, `5/1123`, `2411/23` והאות `O` שזוהתה במקום הספרה אפס. בפרסור סוג A מחושבים ימי השבוע, ותאריכים חסרים משוחזרים רק כאשר התאריכים הסמוכים מאשרים רצף יומי. שעות OCR נפוצות כגון `16•30` ו-`1600` מתוקנות. בפרסור סוג B תאריכים שנפגעו משוחזרים לפי רצף השורות החודשי, ויום השבוע מחושב מהתאריך.

## פענוח וטרנספורמציה

המסווג בוחר סוג דוח נתמך; קובץ לא מזוהה או קובץ שפוענח ללא שורות נוכחות אינו משמש להפקת דוח. בחירת הפרסר נעשית דרך `parser_factory`. כל פרסר מחזיר `AttendanceReport` עם מודל השורה המשותף `AttendanceRow`; לוגיקת הפענוח הייחודית נשארת מותאמת לפורמט של כל סוג.

בחירת סוג הדוח נעשית דרך מיפויי רישום ולא דרך שרשרת `if/elif`: כללי הזיהוי נמצאים ב-`CLASSIFIER_SCORERS` שב-`parsing/classifier.py`, וה-parserים ב-`PARSER_FACTORIES` שב-`parsing/parser_factory.py`. אסטרטגיות הטרנספורמציה רשומות במיפוי שב-`transformation/strategies.py`, ומדיניות הסיכום נמצאת ב-`TransformationConfig` שב-`transformation/config.py`.

הגדרות כלליות כגון תעריף, טווח היסטי השעות, דיוק ומדיניות סיכום מרוכזות ב-`TransformationConfig`. למשל, שינוי גבולות ההיסט נעשה בשדות `minimum_shift_minutes` ו-`maximum_shift_minutes`. ברירת המחדל מזיזה את זמני הכניסה והיציאה בנפרד בהיסט שאינו אפס, בטווח של 5 דקות לאחור עד 10 דקות קדימה. seed יציב לכל שורה מבטיח שאותה שורה ואותו seed יניבו אותה תוצאה גם בהרצות חוזרות וללא תלות בסדר השורות.

במחוללי ה-PDF וה-Excel, עיצוב הדוחות נבחר באמצעות `PDF_LAYOUTS` ו-`EXCEL_LAYOUTS`. הוספת סוג דוח דורשת לממש ולרשום את התמיכה המתאימה במקומות הרישום, אבל אינה דורשת להרחיב שרשרת `if/elif` קיימת. הוספת פורמט פלט חדש נעשית בתוך `generation/`: מוסיפים renderer ורושמים factory ב-`generation/output_registry.py`; שכבת היישום מפיקה את כל הפלטים הרשומים באופן כללי.

לאחר שינוי השעות, שעות העבודה מחושבות מחדש לפי זמן היציאה פחות זמן הכניסה, בניכוי הפסקה כשישנה. בדוחות סוג A גם חלוקת השעות בין שבת, 150%, 125% ו-100% מתעדכנת כך שתסתכם בסך השעות. הסיכום והתשלום מחושבים מחדש. הטרנספורמציה מחזירה דוח חדש ואינה משנה את המודל המקורי.

שגיאות צפויות מסווגות בהיררכיה שב-`domain/exceptions.py`: שגיאות שורת פענוח, סוג דוח לא נתמך ושגיאות טרנספורמציה יורשות מ-`AttendanceConverterError`. ערך פגום אינו מומר בשקט לאפס; במקרה של שגיאה לא מופק פלט לאותו קובץ, והעיבוד ממשיך לקבצים האחרים.

## קובצי פלט

לקובץ מקור בשם `report.pdf` ייווצרו בתיקיית הפלט:

- `NEW_report.pdf`
- `NEW_report.xlsx`

שדות שעות ריקים בפלט מסומנים ב-`---`. אם קובץ פלט קיים נעול, הכלי שומר בשם חלופי ומציג אזהרה. קובצי המקור אינם משתנים. בסיום העיבוד מוצג סיכום, וקוד היציאה מציין אם קובץ אחד או יותר נכשלו.

## מבנה הפרויקט

```text
main.py                    נקודת הכניסה ותהליך הריצה
application.py             ארגומנטים, קלט, עיבוד דוחות והודעות מצב
parsing/                   חילוץ OCR, זיהוי סוג הדוח ופענוח הנתונים
transformation/            אסטרטגיות טרנספורמציה וחישוב הסיכום
transformation/config.py   תעריף, היסטי שעות, דיוק ומדיניות סיכום
domain/                    מודלים משותפים, ReportType וכלי המרת שעות
generation/                יצירת קובצי PDF ו-Excel, רישום layouts ופורמטי פלט
tests/                     בדיקות אוטומטיות
data/sample_reports/       דוחות לדוגמה
data/output_reports/      תיקיית ברירת המחדל לקבצים שנוצרו
data/text_cache/           מטמון הטקסט שחולץ
```

## פתרון תקלות

- **שגיאה באתחול OCR:** יש לוודא שההרצה מתבצעת ב-Windows ושחבילת השפה הנדרשת מותקנת.
- **לא נמצאו קובצי PDF:** יש לבדוק את נתיב הקלט ולוודא שבתיקייה יש קובצי PDF. החיפוש אינו כולל תיקיות משנה.
- **קובץ לא זוהה כדוח:** יש לוודא שזה דוח מסוג A או B ושחילוץ הטקסט הצליח. לקובץ סרוק אפשר לנסות שוב עם `--force-ocr`.
- **PDF בעברית לא מוצג כראוי:** יצירת ה-PDF משתמשת בגופן Arial של Windows כאשר הוא זמין.
