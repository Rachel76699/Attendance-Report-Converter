# Attendance Report Converter

כלי Python לעיבוד דוחות נוכחות בפורמט PDF ולהפקת דוחות PDF ו-Excel.

## יכולות

- חילוץ טקסט מקובצי PDF דיגיטליים ושימוש ב-OCR של Windows לעמודים סרוקים.
- זיהוי אוטומטי של דוחות נוכחות מסוג `TYPE_A` ו-`TYPE_B`, כולל דוחות סוג B שכותרותיהם נפגעו ב-OCR.
- הודעת שגיאה לקובץ שאינו מזוהה או שאין בו שורות נוכחות, ללא הפקת דוח שגוי.
- מודל משותף `AttendanceReport`/`AttendanceRow`; בחירת הפרסר נעשית דרך `parser_factory`, והפענוח הייחודי נשאר בכל פרסר.
- שגיאת פענוח מפורשת לערכים מספריים פגומים, במקום המרה שקטה לאפס.
- שעות הכניסה והיציאה בסוג B נקראות לפי מיקום העמודות בדוח.
- שמירת שורות שבת וחג. שעות הכניסה, היציאה וההפסקה נשארות ריקות; סך השעות נשמר.
- סיכומי שעות, ימי עבודה ותשלום, והפקת PDF ו-Excel לכל דוח.
- שעות ריקות בפלט מוצגות כ-`---`. בדוחות מסוג A מוצגים גם המקום, היום והתאריך שחולצו.
- אם קובץ פלט קיים נעול, נשמר פלט בשם חלופי עם הודעת אזהרה.
- עיבוד קובץ PDF יחיד או כל קובצי ה-PDF בתיקייה, ללא סריקת תיקיות משנה.

## דרישות

- Windows 10 או Windows 11 עבור OCR של Windows.
- Python 3.10 ומעלה.
- חבילת שפה עברית של Windows לזיהוי OCR בעברית. בלעדיה, זיהוי שדות בעברית עלול להיות חלקי.

## התקנה

יש לפתוח PowerShell בתיקיית הפרויקט ולהריץ:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

אם הפעלת סקריפטים חסומה ב-PowerShell, אפשר להפעיל את הסביבה מתוך Command Prompt:

```bat
.venv\Scripts\activate.bat
```

## הפעלה

עיבוד כל קובצי הדוגמה ושמירת התוצאות בתיקיית ברירת המחדל:

```powershell
python main.py
```

עיבוד תיקייה מסוימת:

```powershell
python main.py "data/sample_reports" --output "data/output_reports"
```

עיבוד קובץ יחיד:

```powershell
python main.py "data/sample_reports/report.pdf" -o "data/output_reports"
```

כדי לעקוף את מטמון הטקסט ולחלץ מחדש (כולל OCR לעמודים סרוקים):

```powershell
python main.py "data/sample_reports" --force-ocr
```

הצגת אפשרויות שורת הפקודה:

```powershell
python main.py --help
```

הארגומנט הראשון הוא קובץ PDF או תיקייה. אפשר לציין את תיקיית הפלט באמצעות `-o` או `--output`. ברירות המחדל הן `data/sample_reports` ו-`data/output_reports`.

## חילוץ טקסט ומטמון OCR

הטקסט שחולץ מכל PDF נשמר ב-`data/text_cache` בקובץ UTF-8 ששמו מבוסס על hash של תוכן ה-PDF והגדרות ה-OCR. חילוץ דפים סרוקים מתבצע ברזולוציה של 300 DPI. בהרצה חוזרת, אם הקובץ והגדרות ה-OCR לא השתנו, הטקסט נקרא מהמטמון. שינוי בקובץ או בהגדרות יוצר מפתח מטמון חדש. טקסט ריק אינו נשמר, כדי לאפשר ניסיון חילוץ נוסף בהרצה הבאה.

האפשרות `--force-ocr` עוקפת את המטמון ומחלצת את הטקסט מחדש. לאחר חילוץ מוצלח, המטמון מתעדכן. ללא האפשרות, השימוש הרגיל במטמון נשאר ללא שינוי.

ניקוי ה-OCR מתקן שיבושים שנצפו בדוחות הדוגמה, לרבות תאריכים כגון `01102/2023`, `20/1123`, `5/1123`, `2411/23` והאות `O` שזוהתה במקום הספרה אפס. בפרסור סוג A מחושבים ימי השבוע, ותאריכים חסרים משוחזרים רק כאשר התאריכים הסמוכים מאשרים רצף יומי. שעות OCR נפוצות כגון `16•30` ו-`1600` מתוקנות. בפרסור סוג B משוחזרים תאריכים שנפגעו לפי רצף השורות החודשי, ויום השבוע מחושב מהתאריך. קובצי בדיקות הרגרסיה נמצאים ב-`tests/test_transformation.py`.

## עיבוד נתונים

הפרסרים מחזירים את המודל המשותף `AttendanceReport`. שירות הטרנספורמציה בוחר אסטרטגיה לפי סוג הדוח (`ReportType`), בלי תנאי לפי סוג הדוח בתוך השירות. דוח שעבר טרנספורמציה הוא אובייקט חדש; הנתונים המקוריים אינם משתנים.

שינויי השעות והגדרות הסיכום מרוכזים ב-`TransformationConfig` שב-`transformation/config.py`. ברירת המחדל מזיזה את זמני הכניסה והיציאה בנפרד בהיסט שאינו אפס, בטווח של 5 דקות לאחור עד 10 דקות קדימה. ה-seed לכל שורה מחושב באופן יציב באמצעות BLAKE2, ולכן אותה שורה ואותו seed מניבים אותה תוצאה גם בהרצות חוזרות, בלי תלות בסדר השורות.

אחרי שינוי השעות, משך העבודה מחושב מחדש לפי זמן היציאה פחות זמן הכניסה, בניכוי הפסקה כשישנה. בדוחות סוג A מתעדכנת גם חלוקת השעות בין שבת, 150%, 125% ו-100%, כך שסכומה תואם לסך השעות. הסיכום והתשלום מחושבים מחדש בהתאם.

כל שורה שעברה טרנספורמציה נבדקת: שעות השעון בתחום יום, היציאה אחרי הכניסה, סך השעות בתחום המותר, ובדוח סוג A חלוקת השעות שווה לסך השעות. שבת וחג נשארים ללא שעות כניסה, יציאה והפסקה, וסך השעות שלהם נשמר.

אם ערך מספרי בשורת נוכחות אינו תקין, מתקבלת שגיאה שמציינת את השדה ואת השורה. לא מופק פלט שגוי עבור אותו קובץ, והעיבוד ממשיך לקבצים האחרים.

## קובצי הפלט

לקובץ מקור בשם `report.pdf` ייווצרו בתיקיית הפלט:

- `NEW_report.pdf`
- `NEW_report.xlsx`

קובצי המקור אינם משתנים. אם קובץ פלט נעול או מתרחשת שגיאה בעיבוד, תוצג הודעה והכלי ימשיך לקובץ הבא. קוד היציאה יציין אם קובץ אחד או יותר נכשלו.

## מבנה הפרויקט

```text
main.py                    נקודת הכניסה ותהליך הריצה
application.py             ארגומנטים, קלט, עיבוד דוחות והודעות מצב
parsing/                   חילוץ OCR, זיהוי סוג הדוח ופענוח הנתונים
transformation/            אסטרטגיות טרנספורמציה וחישוב סיכום
transformation/config.py   היסטי שעות, תעריף, דיוק ומדיניות סיכום
domain/                    מודלים משותפים, ReportType וכלי המרת שעות
generation/                יצירת קובצי PDF ו-Excel
tests/                     בדיקות אוטומטיות
data/sample_reports/       דוחות לדוגמה
data/output_reports/      תיקיית ברירת המחדל לקבצים שנוצרו
```

## פתרון תקלות

- **שגיאה באתחול OCR:** יש לוודא שההרצה מתבצעת ב-Windows ושחבילת השפה הנדרשת מותקנת.
- **לא נמצאו קובצי PDF:** יש לבדוק את נתיב הקלט ולוודא שבתיקייה יש קובצי PDF. החיפוש אינו כולל תיקיות משנה.
- **הקובץ לא זוהה כדוח:** יש לוודא שזה דוח מסוג A או B ושחילוץ הטקסט הצליח. לקובץ סרוק אפשר לנסות שוב עם `--force-ocr`.
- **לא ניתן להפיק PDF בעברית כראוי:** יצירת ה-PDF משתמשת בגופן Arial של Windows כאשר הוא זמין.
